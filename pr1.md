## Техническая реализация базы данных (на основе требований ОП.06)

Для корректной работы системы необходимо спроектировать базу данных `library_db` и обеспечить её целостность.

### 1. Структура базы данных
Необходимо создать следующие таблицы (по аналогии с учебным проектом):
* **Таблица «Читатели»** (аналог «Студенты»): `reader_id`, ФИО, дата рождения, адрес, телефон.
* **Таблица «Книги»** (аналог «Дисциплины»): `book_id`, название, инвентарный номер, год издания, количество страниц.
* **Таблица «Авторы»** (аналог «Преподаватели»): `author_id`, ФИО, отдел/секция.
* **Таблица «Выдачи»** (аналог «Занятия»): `issue_id`, `reader_id`, `book_id`, дата выдачи, дата возврата, статус.

### 2. Ограничения целостности и ключи
При создании таблиц необходимо задать следующие ограничения:
* **PRIMARY KEY и AUTO_INCREMENT:** для первичных ключей (`reader_id`, `book_id`, `issue_id`).
* **FOREIGN KEY:** для связывания таблиц (например, `issue.reader_id` ссылается на `readers.reader_id`).
* **NOT NULL:** для обязательных полей (ФИО читателя, название книги).
* **UNIQUE:** для уникальных значений (например, инвентарный номер книги).
* **CHECK:** для логических условий (например, `pages_count > 0` или `return_date >= issue_date`).

### 3. Ссылочная целостность и каскадные операции
* **Каскадное обновление (ON UPDATE CASCADE):** если изменяется ID читателя или книги, связанные записи в таблице «Выдачи» обновятся автоматически.
* **Каскадное удаление (ON DELETE CASCADE):** применять осторожно. Например, при удалении читателя из базы автоматически удаляются его архивные записи о выдачах.
* **Проверка целостности:** система не должна позволить выдать книгу несуществующему читателю (операция должна завершиться ошибкой внешнего ключа).

### 4. Схема данных (ER-диаграмма)
Создать графическую схему базы данных, отображающую связи «один ко многим» (1:N):
* Один читатель → много выдач.
* Одна книга → много выдач.

### 5. SQL-скрипт
Создать единый файл `library_db.sql`, который включает:
1. Создание и выбор БД.
2. Создание таблиц с ограничениями.
3. Заполнение тестовыми данными (минимум 10 записей в каждую таблицу различными способами).
4. Тестовые запросы для проверки каскадных операций и ссылочной целостности.
